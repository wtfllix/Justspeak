xxspeak 产品需求文档
产品需求与技术实施基线 v1 0
Windows 优先 · 四人内测 · 自托管游戏语音
xxspeak 面向一起玩游戏的小型固定团队，提供轻量、无广告、中文优先的语音体验。管理员部署自己的 Voice Server 并向官方 Registry 注册服务器 ID；玩家无需注册云账号，输入 ID 和昵称即可连接。日常使用窄窗口频道树，需要调麦克风时向右展开设置面板。
本文用于产品评审、架构设计、任务拆分和测试验收。五项交互决策为固定基线；接口字段、数据库结构、超时和安全实现细节属于工程建议，需在相应里程碑中验证并固化。

1 产品定位与范围
1 1 产品要解决的问题
固定游戏小队需要随时开口交流，但不希望为了语音承受广告、资讯、社交动态和复杂导航。xxspeak 将连接、选频道、说话、调麦克风作为主路径，同时让管理员掌握服务器配置、权限和部署位置。
核心价值是“管理员部署一次，玩家凭 ID 加入”。官方 Registry 承担注册和地址解析，语音流量由玩家直连自托管服务，官方不转发或保存语音内容。
1 2 产品原则
• 语音优先：启动和连接后直接呈现服务器、频道和成员。
• 操作简单：普通玩家不需要理解 IP、端口、WebRTC 或 LiveKit。
• 小窗口：高频操作集中在左侧，设置按需展开，游戏中可隐藏到托盘。
• 自托管：服务器配置、权限和媒体转发位于管理员控制的基础设施。
• 官方最小化：Registry 管理发现和所有权，不能代替 Voice Server 授权。

3 1 草图的设计约束
连接界面保留书签下拉框、服务器 ID、昵称、“仅本次连接”和“连接并收藏”两个按钮；服务器要求密码时再弹窗。主界面保留服务器与频道树、频道下的成员列表、底部连接状态、Settings 入口和窗口缩放能力。

3 2 尺寸建议
采用 Windows 逻辑像素作为设计单位：连接窗约 320 × 360，主窗约 320 × 480，最小约 280 × 360；右侧增加约 340，允许在 320–380 范围内调整。实际尺寸以 100%–200% DPI、文字缩放和小屏验证结果为准。

4 2 连接行为
点击连接后禁用重复提交，但保留取消操作。取消后迟到的响应不能继续自动加入。已连接时切换服务器，先明确结束旧媒体与控制会话，避免同时向两个服务器发送音频。高级直接地址入口不占据主连接表单。

错误不应清空全部输入，也不应把“信令已连接”显示成“语音可用”。详细诊断写入脱敏日志，普通界面不暴露堆栈、Token 或密钥。

个人音量建议 0%–200%、步长 5%，按服务器身份与远端身份保存。超过 100% 时应避免削波。隐藏在右键菜单的操作需有键盘可达入口；频道加入可补充 Enter，双击规则保持不变。
5 2 横向展开
点击设置后向右展开麦克风设置，收起时恢复窄窗口，左侧选中项、滚动位置和语音不变。首次默认收起；后续恢复用户上次面板状态。屏幕右侧空间不足时向左调整位置，保证窗口位于可见工作区。
主窗口可调整宽高，保存位置、尺寸和面板状态。显示器数量、分辨率或 DPI 变化后重新约束位置。键盘焦点和朗读标签应覆盖树、静音、音量和展开控件。
5 3 托盘与退出
默认关闭按钮隐藏到托盘，首次明确提示语音仍在继续；托盘菜单提供显示窗口、静音和退出。明确退出时停止采集、释放设备、注销快捷键并结束会话。隐藏、React 重绘和设置展开都不得中断语音。

6 1 简洁面板
默认优先显示麦克风区域。设置即时反馈，失败时回滚到可用配置并说明原因；设备与偏好在本地保存，下次启动恢复。

降噪模式为关闭、标准、AI。标准采用 WebRTC 音频处理能力，AI 采用本地 RNNoise 路线。[R06] 本产品的 AI 降噪由客户端集成，不能仅因部署 LiveKit 就宣称具备该能力；模型、许可和性能需单独验证。
6 2 试听与设备切换
麦克风测试需有明确开始、停止和正在测试状态，默认不向频道发送试听内容。对比关闭和开启降噪的同一段本地样本，允许用户主动保存；默认不上传、不后台留存原始音频。若采用回放，应防止扬声器回灌并在测试前提示使用耳机。
拔出当前设备时保持应用稳定，显示设备不可用并停止无效采集。可以回退到系统默认设备，但须先进入静音并提示用户，避免未经察觉切换到外放或其他麦克风。重新插入后可恢复选择，避免自动开麦。
6 3 自由麦与 PTT
自由麦默认采用 VAD 的方案在 M1 验证，持续发送放在高级设置。PTT 按下才允许发送，松开立即关闭发送门；快捷键录入时检测冲突并允许重设。模式切换、失去按键释放事件、系统锁屏和设备切换时重置为未按下。
全局 PTT 必须在约定测试游戏占据焦点时验证。兼容性记录包含游戏、窗口模式、权限等级和设备；不承诺所有游戏、反作弊系统或管理员权限组合均可使用。故障时提供可见的手动静音与自由麦切换入口。
7 普通玩家与管理员流程
7 1 玩家首次连接
1. 启动应用，自动创建并安全保存本地身份；普通玩家无需云账号。
2. 输入服务器 ID 与昵称，选择本次连接或连接并收藏。
3. Registry 解析地址与服务器公钥指纹，客户端执行地址和身份校验。
4. 使用挑战签名证明身份；按服务端要求输入服务器密码。
5. 获取控制会话和频道列表，首次尝试服务器默认频道。
6. 服务端检查频道权限及容量，签发限定房间的媒体 Token。
7. 媒体接通后显示当前频道和发言状态；按需保存书签。
7 2 日常连接与游戏使用
选择书签后沿用昵称与身份，重新校验服务器，再尝试上次成功频道。不可进入则回退默认频道；默认也不可进入时保持服务器连接并说明原因。主动离开频道后本次会话不因重连而自动入房；用户关闭自动恢复时同样保持手动选择。
玩家双击切换频道、右键调整朋友音量，点击麦克风静音，需要时展开设置。隐藏窗口后继续语音与 PTT，明确退出后停止媒体。断网时提示重连，网络恢复后重新校验会话与权限。
7 3 管理员首次部署与注册
1. 准备 Linux VPS、域名、证书、持久化目录和必要防火墙规则。
2. 用 Docker Compose 启动 Fastify API 与 LiveKit，初始化 SQLite 和服务器身份。
3. 通过受保护的本机初始化入口创建一次性绑定码，并向 Registry 建立短期绑定意图。
4. 登录官网管理员账号，输入绑定码，核实服务器名称和指纹并提交绑定。
5. Registry 原子消费绑定意图并分配唯一 8 位 ID；服务端领取结果并持久化。
6. 用另一个客户端输入 ID 完成加入验证；向自己的本地玩家身份授予服务器管理权限。
Registry 账号只管理服务器所有权，不自动成为 Voice Server 的管理员。首次本地管理员授权需通过部署控制台或受保护的一次性引导凭据完成，不能让“第一个连接者”自动获得权限。
7 4 管理与迁移
管理员在客户端管理频道、人数限制、密码及成员权限。迁移时停写并备份数据库与服务器私钥，在新节点恢复，证明同一服务器身份后更新 Registry 地址并递增地址版本。玩家保留原 ID；私钥丢失时走所有权恢复流程，禁止静默替换指纹。

8 1 分离控制连接和媒体连接
服务器登录不等于已加入语音频道。客户端需要分别维护控制会话、频道列表、选中频道、实际加入频道和媒体健康状态。

已连服务器但未入频道
可浏览频道、手动加入；显示未接通语音
频道加入或切换中
显示目标与进度；禁用重复切换；不提前更新当前频道

8 2 频道切换事务建议
一个稳定频道 ID 对应一个 LiveKit Room，建议名称包含服务器 UUID 与频道 UUID。频道重命名不改变 Room 标识。界面中的人数应结合有效会话与媒体事件计算，不能单凭 SQLite 在线标志。
推荐首版采用明确的顺序切换：先申请并预检目标，准备切换后静音、退出旧房间，再加入目标；成功才写入上次频道并广播新状态。失败则显示未入频道并允许返回旧频道，返回时重新申请权限；不承诺无缝切换。
join 请求带 operationId 和会话代次，服务端对容量预留设超时，客户端取消或被新操作替代后丢弃迟到结果。任何时刻每个客户端只向一个频道发布音频。
8 3 重连与降级
建议重试间隔 1、2、4、8 秒后上限 15 秒并加入随机抖动，具体值经测试固化。用户可取消；封禁、撤销、密码错误和身份不匹配不盲目重试。重连后拉取完整快照再接增量事件，避免重复成员或幽灵在线。
Registry 故障不影响已有直连通话。Voice API 暂时不可用时，已建立媒体可短时保留，但管理和新加入暂停；客户端不能在无法验证权限时自行创建新媒体会话。

10 音频管线与技术验证
10 1 推荐媒体路径
WASAPI Capture -> Format / Resample -> AEC with playback reference
 -> Standard NS OR RNNoise -> Gain / Limiter -> VAD + PTT Gate
 -> LiveKit Audio Source -> Opus / WebRTC -> SFU
Remote Track -> Decode -> Per user gain / mute -> Mix -> WASAPI Render
                                         -> AEC reference
以上为待 PoC 验证的处理拓扑，不是 SDK 默认行为承诺。AEC、AGC、降噪和 VAD 的顺序及延时必须在实际绑定中验证。避免 SDK 内部处理与自定义 PCM 管线重复降噪、重复增益。PTT 或静音可以保留 AEC 所需参考处理，但发送门必须关闭。
10 2 M0 与 M3 的技术门槛
• M0 验证 LiveKit Rust SDK 在目标 Windows、构建工具链和设备上的采集、播放、音轨订阅与重连；锁定依赖版本。
• 原生设备采集和自定义 PCM 接入各做一次验证；根据 AEC 参考与独立音量支持情况选定生产路径。
• M3 集成 RNNoise，固定模型、帧长、采样格式和转换边界；以录音 A/B 及性能数据判断效果。[R06]
• 扬声器外放、耳机、有线 USB 与蓝牙设备分别测试；不能把耳机场景的结果泛化为所有音频设备。
10 3 实时线程要求
音频回调中避免网络请求、数据库写入、磁盘日志、长锁和频繁分配；使用有界队列并记录丢帧与欠载。必要的重采样、帧缓存和处理引入的延迟纳入端到端预算。设备切换不在回调中同步等待。
发送许可应由“媒体已连接、设备可用、未自我静音、未被禁言、当前模式允许发送”共同决定。UI 的发言指示区分输入电平与实际发送状态，防止用户误以为静音后仍在发送。
10 4 本地试听与质量判断
使用相同语音、键盘声和风扇声样本比较关闭、标准、AI 三种模式，关注吞字、失真、噪声抑制、附加延迟和 CPU。没有测量前不宣称降噪分贝数或主观得分；录音保留需由测试者明确选择。
11 自托管服务端与部署
11 1 组件职责
Fastify API 负责服务器配置、挑战认证、密码、频道与权限、会话、LiveKit Token、管理操作、Registry 注册和心跳。SQLite 是 API 的嵌入式数据库文件，不需要单独运行数据库容器。LiveKit SFU 转发媒体并产生参与者事件；单节点方案不依赖 Redis，未来分布式模式再引入。[R03]
基础 Compose 包含 API 与 LiveKit 两个业务容器，另按部署环境提供 TLS 反向代理；Registry 是官方独立部署，不打包进每台自托管服务器。服务器身份密钥、SQLite 数据和证书必须放在持久卷或专用安全存储中。

12 Registry 注册绑定与生命周期
12 1 身份与 ID
Voice Server 首次启动生成独立的非对称服务器密钥及 UUID。Registry 分配 8 位数字 ID，按字符串传输，随机或安全分配且数据库唯一约束兜底。ID 稳定、不可自选，不承担认证或隐私保护功能。未公开不等于不可被枚举，访问仍由 Voice Server 密码和权限决定。
12 2 一次性绑定协议建议
1. 管理员在部署控制台触发初始化，服务端创建高熵短期绑定码，仅展示一次。
2. 服务端以服务器私钥签名，向 Registry 创建 pending 绑定意图，提交绑定码哈希、公钥、候选地址和过期时间。
3. 管理员登录官网输入绑定码。Registry 校验账号会话、限速、码哈希与有效期，并验证服务器持钥证明与地址可达性。
4. 官网显示服务器名称、地址、指纹供核实；提交时以事务原子消费绑定码、绑定 owner 并分配 ID，避免两个账号抢占同一意图。
5. 服务端用签名查询领取结果，保存 ID、所有权版本和后续通信凭据，立即废弃绑定码。
建议绑定码有效期 10 分钟、失败次数受限，具体长度与速率按威胁测试固化。不得把短数字服务器 ID 同时用作绑定码。码不写普通日志、不放公开 API，超时可重新生成，旧码同步失效。
12 3 心跳与地址更新
服务端签名心跳，包含 ID、时间、nonce、地址版本和软件协议版本。建议 30 秒一次，超过约 90 秒标记心跳过期；这些是待验证配置值。心跳只证明近期控制联络，不证明媒体链路健康。
地址更新必须验证当前服务器密钥和所有权授权，禁止匿名覆盖。新地址验证通过后原子递增 endpointVersion，保留审计记录；Registry 不根据未认证的来源 IP 自动改地址。
12 4 解绑转移与丢失恢复
解绑、转移和撤销需要管理员账号重新认证，记录操作并废止旧管理凭据。所有权转移建议同时要求旧 owner 确认、新 owner 接受和服务器持钥证明。ID 保留或冻结，不立即回收给陌生服务器，避免旧书签误连。
服务器密钥轮换通过旧密钥签署新公钥和版本；密钥丢失时走单独恢复审查，客户端必须看到身份变化，不能仅凭同一 ID 自动信任新密钥。
13 Registry 解析信任与故障降级
13 1 解析与服务器验证
客户端通过固定官方 HTTPS 域名查询 ID，取得 API 地址、业务服务器 UUID、公钥指纹、地址版本、状态、签发时间和有效期。建议响应带 Registry 数字签名，以便验证缓存完整性和有效期；首次信任根随客户端发布，轮换规则单独版本化。
随后连接 Voice Server 的 HTTPS API，校验 TLS，再由服务端用对应服务器私钥签署客户端随机挑战。公钥指纹必须与 Registry 和已有书签一致。TLS 验证、Registry 签名与服务器持钥证明解决不同信任环节，不能相互替代。
13 2 地址防护
官方 Registry 路径只允许 HTTPS API 地址与明确允许的 WSS 媒体地址。默认拒绝回环、私网、链路本地、云元数据、保留地址、危险端口和含凭据的 URL，同时覆盖 IPv4、IPv6 与混合编码。DNS 解析后校验目标，重定向与重解析再次校验，防止 DNS 重绑定。
以上策略同时适用于 Registry 的地址探测器，探测器应隔离出站网络并设置连接、响应大小和重定向上限。合法局域网部署走单独的高级直连模式，由用户明确确认目标与身份，不通过官方公共地址解析默认放行。

建议在线缓存 TTL 为 5 分钟，明确离线降级窗口最多 24 小时，最终值需在 M4 固化。使用缓存时显示最近验证时间，仍检查 TLS 和服务器持钥证明；禁止接受低于本地已知 endpointVersion 的响应。
13 4 降级的边界
Registry 离线时，客户端无法获知刚发生的撤销。离线窗口是在可用性与撤销传播之间的权衡，不承诺即时全网撤销。缓存仅帮助找到同一服务器，不跳过用户认证、服务器密码、封禁与频道授权。长时间离线必须重新在线验证。
14 本地身份权限与安全
14 1 玩家身份
首次启动建议生成 Ed25519 密钥，identityId 由规范化公钥计算稳定指纹。私钥经 Windows DPAPI 或系统凭据库保护，不通过 React、网络或日志传出。昵称仅为显示名，同名不合并；重装或密钥丢失视为新身份，除非成功恢复备份。
挑战签名负载必须包括协议域、服务器 UUID、会话上下文、随机 nonce、challengeId 和有效期。服务端校验算法、公钥、签名及请求归属，挑战短期有效、一次性消费并限速，防止重放或跨服务器复用。权限不能依赖客户端自行声明的 user_id。
全局本地身份可能使不同自托管服务器关联同一用户，隐私说明需披露；按服务器派生身份可作为后续方案，不能在 v1.0 静默改变权限标识。身份导出使用口令加密并提醒丢失风险；恢复前校验指纹，避免覆盖错误身份。

14 3 媒体凭证与立即撤权
LiveKit Token 仅允许指定房间的音频发布与订阅，不授予管理、视频或录制能力。自托管 LiveKit 移除参与者并不会自动使旧 Token 失效；Token 到期也不等于既有连接立即终止。[R07]
M4 必须同时撤销业务会话、停止签新 Token、移除参与者并验证旧 Token 重入。建议增加媒体信令准入检查：每次新连和恢复连接校验有效会话及房间代次，阻断直达信令绕过；其与 SDK 自动刷新行为的兼容性必须先 PoC。短 TTL 只能缩小风险窗口，不能作为“封禁立即生效”的证明；未解决旧凭证重入不得通过公开测试安全门槛。

16 2 快照与增量事件
控制 API 提供版本化快照和递增 seq 的事件流。建议事件包括 channel.created、channel.updated、channel.deleted、member.joined、member.left、member.moved、member.speaking、permission.changed、session.revoked 和 server.updated。重连出现序号缺口时重新取快照。
LiveKit webhook 验签、防重放并幂等消费；媒体事件与业务操作可能乱序，要以 mediaSessionId 和会话代次关联。前端发来的“在线”或“正在说话”不作为权限事实，音频电平事件应限频。
16 3 错误与可靠性
建议统一返回 {error:{code,message,retryable},requestId}。常见状态：400 参数错误，401 身份或会话无效，403 禁止访问，404 不存在，409 版本冲突或频道满，429 限流，503 临时不可用。业务 code 区分 PASSWORD_REQUIRED、CHANNEL_FULL、BANNED、IDENTITY_MISMATCH 等。
创建、加入与管理操作支持幂等键或 operationId；相同身份、操作和键的重复请求返回同一结果，不可重复签发互相冲突的会话。审计记录保留操作者、目标、结果、版本和 requestId，不包含密码与完整凭据。

18 2 一致性与索引
开启外键，定义删除策略。频道 parent_id 防环；默认频道必须存在且允许合适的入场策略。容量检查与预留需原子执行，超时释放。频道、权限、会话使用 UUID 等不透明 ID，不依赖可变昵称。

18 3 在线状态与重启

SQLite 使用本地持久磁盘、短事务、忙等待与迁移版本表；WAL 可改善读写并行，但仍需处理写锁与 SQLITE_BUSY。[R08] 不把四人内测容量推断成任意规模可用。
